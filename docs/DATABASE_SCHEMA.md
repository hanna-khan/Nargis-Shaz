# Database schema

MySQL 8.0 (InnoDB, `utf8mb4_0900_ai_ci`). The schema is defined in `src/server/db/schema.ts` (Drizzle ORM) and applied by the SQL migrations in `drizzle/migrations`.

## Conventions

- **Primary keys** are 26-character ids (`varchar(26)`, generated by `newId()`). Lookup tables use natural keys, for example `currencies.code` and `countries.code`.
- **Money** is stored as integer minor units (`bigint`): paisa, pence or cents. Every money column has a matching currency code. Prices are set per currency (`product_prices`, `variant_prices`); exchange rates are only a fallback.
- **Timestamps** are `datetime(3)` in UTC. Reports convert them to Asia/Karachi.
- **Soft state, not deletes.** Orders, payments and audit rows are never deleted. Products are archived via `status`. Hard deletes are limited to rows nothing references; the media library checks usage first.
- **Secrets are never stored in plain text.** Session, reset, invitation and verification tokens are stored as SHA-256 hashes. Passwords use Argon2id.
- **Binaries live outside MySQL.** `media_assets` holds the storage key, dimensions and renditions; the bytes are in R2.
- **Concurrency rules:**
  - Stock is reserved with guarded single-statement updates (`on_hand - reserved >= ?`).
  - Coupons are read with `SELECT … FOR UPDATE` during checkout.
  - `orders.idempotency_key` is unique, so a checkout submitted twice creates one order.
  - `payment_webhook_events (provider, event_id)` is unique, so each webhook event is processed once.
- **Sequential order numbers** come from the `sequences` table: a row lock is taken inside the checkout transaction, producing the store prefix (Settings) followed by a counter that starts at 10001.

## Migrations

| `0001_order_cart.sql` | Order ↔ cart link and checkout idempotency |

- `npm run db:migrate` applies pending migrations. It is forward-only, and each file runs once, tracked in `__drizzle_migrations`.
- To change the schema, edit `schema.ts`, run `npm run db:generate`, review the generated SQL, then commit it.
- Never edit a migration that has already run in production.

## Seeding

`npm run db:seed` is idempotent and safe to run against production:

- **Reference data is insert-if-missing.** This covers currencies, markets, countries, tax, shipping, payment methods, roles and permissions, templates, settings, menus and policies. Existing rows are never overwritten.
- **The catalogue import** (the 17 launch products) only runs when `products` is empty.
- **The first owner** is created from `SEED_OWNER_EMAIL` / `SEED_OWNER_PASSWORD` only if no staff account holds the owner role.

`npm run db:seed:reference` loads reference data only, with no catalogue.

## Entity overview

```
users ─┬─ customer_profiles, customer_addresses, user_sessions, customer_notes
       ├─ carts ── cart_items ── product_variants
       ├─ wishlists ── wishlist_items ── products
       └─ orders ─┬─ order_items (snapshot of name/sku/price) ── product_variants
                  ├─ order_addresses (shipping, billing)
                  ├─ order_status_history, order_notes
                  ├─ stock_reservations ── inventory ── product_variants
                  ├─ payments ── payment_transactions, refunds
                  ├─ shipments ── shipment_events
                  ├─ returns ── return_items
                  └─ coupon_redemptions ── coupons
products ─┬─ product_variants ─┬─ variant_prices, inventory
          │                    └─ product_attribute_values (size, colour)
          ├─ product_prices, product_images ── media_assets
          ├─ product_categories ── categories
          ├─ product_collections ── collections
          └─ related_products
staff_users ── staff_role_assignments ── roles ── role_permissions ── permissions
markets ─┬─ countries, currencies, shipping_zones ── shipping_methods
         └─ payment_methods (per market)
```
